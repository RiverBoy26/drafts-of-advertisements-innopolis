# Результаты экспериментов

Дата: 2026-11-14. Исследовательская машина: Windows, 16 GB RAM, 12 логических CPU, NVIDIA GeForce RTX 3050 8 GB; CPU-классификатор обучен Python 3.11, GPU-эксперименты — PyTorch 2.11.0+cu126. Train метки предоставлены организаторами и являются слабыми автоматически созданными метками, не экспертным gold.

## Расширенное сравнение классификаторов

10 000 исходных строк после нормализации и точной дедупликации дали 4 854 уникальных описания. Для выбора использованы пять одинаковых `GroupShuffleSplit` фолдов (seed 42, 7, 21, 101, 2026) по компонентам near-duplicate графа: cosine ≥0.95, всего 4 074 компоненты. В каждом фолде 80% компонент train и 20% validation. Все значения ниже — среднее по пяти фолдам, threshold=0.45; std указан для micro-F1. Разбиения и предсказания записаны локально в `ai-service/work/` (эти файлы не входят в git).

`*` Для word варианта округлённое стандартное отклонение — 0.006; исходный отчёт доступен в `ai-service/work/benchmark_models.json`.

Выбран CPU вариант `char_wb` 3–5 с `min_df=2`, C=200, sublinear TF, порогом 0.45; на полном наборе он даёт 100 962 признака. Тест увеличения лимита словаря дал средний micro-F1 0.9395 (cap 150k), 0.9395 (cap 250k) и 0.9395 (cap 350k/min_df2), различия меньше 0.0002. Без sublinear TF результат упал до 0.9259. Threshold sweep для выбранного варианта: 0.40 — F1≈0.9399, P≈0.9330, R≈0.9469; 0.45 — F1≈0.9397 pooled, P≈0.9373, R≈0.9420; выбрано 0.45 для более высокой precision при практически равном F1.

Трансформер `cointegrated/rubert-tiny2` на тех же пяти grouped фолдах: средний micro-F1 около 0.9303, уступает CPU модели. `DeepPavlov/rubert-base-cased` на RTX 3050 (длина 512, effective batch 8, три эпохи) получил на held-out фолдах F1 0.9501, 0.9636, 0.9606, 0.9667, 0.9405; среднее 0.9563, std 0.0097. Средние precision/recall/MAP при пороге 0.45: 0.9383/0.9751/0.9619. Пиковая VRAM около 3.8 GB, полный фолд обучался около 9.5 минут.

Смешивание вероятностей RuBERT и CPU-модели 50/50 на тех же пяти фолдах: micro-F1 0.9624 (std 0.0052), macro-F1 0.9621, precision 0.9438, recall 0.9817, MAP 0.9833 при пороге 0.475. Порог 0.45 дал практически тот же F1 — 0.9623 — с большей полнотой. Веса и порог подобраны на development фолдах, поэтому это кандидат для использования, а не независимый финальный score. Полный анализ и воспроизведение: `scripts/benchmark_rubert_base.py` и `scripts/benchmark_ensemble.py`.

Полный CPU train артефакт собран командой `python scripts/train_cpu.py`: `ai-service/artifacts/cpu_char.joblib`, размер сжатого файла 4.1 MB. Финальная RuBERT модель обучена на всех 4 854 уникальных train описаниях командой `python scripts/train_rubert_base.py` и сохранена в локальную игнорируемую папку `ai-service/artifacts/rubert_base/`; веса (715 MB) не добавляются в git. `LOCAL_CLASSIFIER_BACKEND=ensemble` включает смешанный inference в CUDA-окружении. Если optional модель не загрузится, сервис сообщает об этом и использует CPU-модель.

Локальный CPU TestClient на тексте «Укладываю плитку и монтирую розетки в ванной» вернул target ID `[103,105]`, классификация 3.96 ms, end-to-end без генератора 5.10 ms, provider calls=0. Официальный ответ с выключенным генератором сохранил категории и вернул null для draft title/text.

## Группированная валидация CPU (исторический односидовый benchmark)

Источник `public-train-annotated.jsonl`: 10 000 исходных строк, 4 854 уникальные нормализованные description группы после удаления дубликатов. Char TF-IDF 3–5 грамм, nearest-neighbor cosine использован для образования connected components на уровне ≥0.95. Получено 4 074 компонента (largest=266); `GroupShuffleSplit(test_size=0.2, random_state=42)` создал 3 928 train и 926 validation уникальных описаний. Максимальная похожесть между train и validation =0.9496; cross-split пар ≥0.95: 0. Остались 70 validation записей с ближайшим train сходством ≥0.90 — этот остаточный риск отражён.

| Модель | Порог | Micro-F1 | Precision | Recall |
|---|---:|---:|---:|---:|
| TF-IDF word (1–2 граммы) + One-vs-Rest Logistic Regression | 0.50 | 0.9094 | 0.9002 | 0.9187 |
| TF-IDF char (3–5 грамм) + One-vs-Rest Logistic Regression | 0.45 | **0.9342** | 0.9252 | **0.9434** |
| Word + char TF-IDF + One-vs-Rest Logistic Regression | 0.50 | 0.9319 | **0.9332** | 0.9306 |

Выбран char-only вариант с порогом 0.45. Это измерение согласия с шумной разметкой, не ожидаемая точность на ручном или закрытом тесте. Предварительный split только по точным описаниям давал завышенный результат и не используется для выбора. Результат near-duplicate анализа воспроизводится `scripts/audit_near_duplicates.py` и stricter evaluation — `scripts/evaluate_cpu.py`.

## Публичный набор организаторов

Финальный отчётный прогон после выбора порога на grouped validation: `public-test-dataset.parquet`, 208 строк, 139 уникальных нормализованных описаний, 69 повторных строк, 24 строки имеют точное описание в train. У файла нет исходного mcId; для измерения принято явно оговорённое допущение `source_mcId=101`. Маппинг `categories` → шесть категорий кейса зафиксирован в `scripts/evaluate_public_test.py`.

| Набор | Micro-F1 | Precision | Recall | Classifier p50 / p95 |
|---|---:|---:|---:|---:|
| Предыдущая char-only модель, порог 0.45 | 0.7982 | 0.7018 | 0.9254 | 8.28 / 16.52 ms |
| Новая char_wb C=200 min_df=2, порог 0.45 | 0.7918 | 0.6939 | 0.9220 | 3.88 / 8.68 ms |
| RuBERT+CPU 50/50 ensemble, порог 0.475 | 0.8211 | 0.7235 | 0.9492 | 22.66 / 39.89 ms |

Этот публичный набор не является независимым слепым тестом: он содержит дубликаты и 24 точных пересечения с train. Публичные данные запускались несколько раз для диагностики разных артефактов/порогов; ни один порог не выбирался по ним. Итоговый порог выбран на near-duplicate validation. Измерение — прозрачный ориентир, не финальный хакатон score.

Предыдущая модель per-class F1: 102=0.7613, 103=0.6327, 104=0.8138, 105=0.8590, 106=0.8769. Новая CPU-модель: 102=0.7368, 103=0.6800, 104=0.8000, 105=0.8344, 106=0.8819. Ensemble: 102=0.7643, 103=0.8000, 104=0.8392, 105=0.8571, 106=0.8372. Различия показывают разброс между grouped train-метриками и маленьким, уже просмотренным публичным набором; по нему модель не настраивалась.

Задержки — локальный `predict_proba` для каждого из 208 текстов, warm process, без генерации и HTTP; не end-to-end заявка. Новая модель на public-test: p50/p95 3.88/8.68 ms. Локальный CPU TestClient вернул категории 103 и 105: классификация 3.96 ms, полный вызов с выключенным генератором 5.10 ms, provider calls=0.
