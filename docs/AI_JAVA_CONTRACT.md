# Контракт Java → Python

`POST /internal/v1/avito/drafts`, JSON `{ "description": "...", "mcId": 101 }`. Ответ HTTP 200 строго `{ "drafts": [{"mcId":103,"title":"..."|null,"text":"..."|null}] }`; дополнительные поля не выдаются. Разрешены только 101–106, исходная категория исключена, дубли отсутствуют. Ошибка входа — 422; недоступный CPU-классификатор — 503; ошибка генерации сохраняет классифицированные `mcId` с `null` полями. Ошибка классификации никогда не маскируется пустым списком.

Java worker вызывает синхронно endpoint из собственного асинхронного workflow. Рекомендуемый timeout 35 секунд, ограниченные повторы только на транспортные сбои. `requestId` генерирует Python для диагностики; Java может передать `X-Request-ID` после реализации middleware. Внутренний bearer auth предусмотрен как требование, но пока не подключён в endpoint. Java должна иметь явное сопоставление старых UUID с шестью ID кейса; нельзя генерировать UUID или подменять отсутствующий исходный `mcId=101`. Старый публичный `text` контракт не соответствует официальной схеме: адаптировать на границе Java. Сохранять null как отсутствие генерации. Автопубликации нет.
