# Контракт Java → Python

`POST /internal/v1/avito/drafts`, JSON `{ "description": "...", "mcId": 101 }`. Ответ HTTP 200 строго `{ "drafts": [{"mcId":103,"title":"..."|null,"text":"..."|null}] }`; дополнительные поля не выдаются. Разрешены только 101–106, исходная категория исключена, дубли отсутствуют. Ошибка входа — 422 (для слишком длинного description — 413); недоступный CPU-классификатор — 503; ошибка генерации сохраняет классифицированные `mcId` с `null` полями. Ошибка классификации никогда не маскируется пустым списком. Если настроен `INTERNAL_API_TOKEN`, внутренние endpoints требуют `Authorization: Bearer <token>`.

Java worker вызывает синхронно endpoint из собственного асинхронного workflow. В Compose read timeout равен 120 секундам с учётом возможных повторов генерации; при изменении режима провайдера его нужно сверять с максимальным временем ответа и ожиданием фронтенда. `requestId` генерирует Python для диагностики; Java может передать `X-Request-ID`. Java уже передаёт целочисленный `mcId` из каталога 101–106 без подмены исходной категории. Сохранять null как отсутствие генерации. Автопубликации нет.
